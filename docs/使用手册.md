## 1. 这份手册能教会你什么

读完并跟着做一遍，你将能够：

- 在 DeepSeek Harness 中确认插件已加载、COMSOL 可用、许可可检出；
- 用一句自然语言让 Agent 建立、求解一个参数化的同轴圆锥微波基准模型；
- 读取 `S11`、`|E|` 最大值/平均值/体积分、指定截线场分布；
- 把结果导出为 CSV 和 PNG，并知道每个文件代表什么；
- 修改参数、重新求解、做小规模参数扫描，并判断每组是否真的成功；
- 在失败时读日志、定位许可/网格/收敛/文件/预览文件等问题；
- 清楚知道当前插件**不能**做什么，避免把“求解成功”误当成“物理正确”。

### 一个必须先记住的原则

> **几何建模成功 ≠ 物理模型正确；求解成功 ≠ 物理结论正确。**

插件会把“进程成功”“模型加载成功”“求解成功”“输出文件生成”“物理假设是否充分”分开报告。你看到 `ok=true` 时，只代表工具链在这一步成功，不代表你的材料参数、边界条件、等离子体模型或实验条件是对的。

## 2. 10 分钟快速开始

### 2.1 前提检查

你只需要确认三件事：

1. 本机安装了 COMSOL Multiphysics 6.2，并且能正常打开；
2. COMSOL 许可可用（能建立一个新模型）；
3. DeepSeek Harness 当前会话已经加载 `comsol-agent` 插件。

第 3 条可以用工具列表确认：向 Agent 说“列出 comsol 工具”，或直接看本文第 5 节。

### 2.2 三步跑通第一次真实仿真

在 Harness 对话框里依次输入：

**第一步：检查环境（会真实检出一个许可，约 20 秒）**

```text
请用 comsol-agent 检查本机 COMSOL 环境，deep=true。
```

对应工具调用：

```text
comsol_check_environment(deep=true)
```

你会看到类似：

```json
{
  "ok": true,
  "comsol": {
    "found": true,
    "home": "D:\\COMSOL62\\Multiphysics",
    "version": "6.2.0.290",
    "license": { "status": "checkout-verified-in-probe" }
  }
}
```

**第二步：建立并求解一个同轴圆锥基准模型**

```text
请用 comsol_create_model 建立 coaxial_conical_gap 模板，
参数：r_in=4.35, r_out=10, z_feed=20, z_tip=60,
r_tip_in=0.5, r_tip_out=6, freq=2.45[GHz], P_in=1[W]，
网格 hauto=4，并立即求解。
```

对应调用：

```text
comsol_create_model(
  template="coaxial_conical_gap",
  name="my_first_conical",
  solve=true,
  meshSize=4,
  templateParams={
    "r_in":"4.35","r_out":"10","z_feed":"20","z_tip":"60",
    "r_tip_in":"0.5","r_tip_out":"6","freq":"2.45[GHz]","P_in":"1[W]"
  }
)
```

预期结果（本机实测）：

- 模型文件：`%USERPROFILE%\comsol-agent-workspace\models\my_first_conical.mph`
- 几何：2D 轴对称，1 个空气域，6 条边界
- 网格：约 122 单元
- 解：`sol1`，约 944 自由度
- `S11 = -0.002612 + 0.253224j`
- `|S11| = 0.253238`，`S11 = -11.93 dB`

**第三步：导出 S 参数和场图**

```text
请对刚才的模型导出 S 参数、|E| 场图和 z=10mm 的径向截线。
```

对应调用：

```text
comsol_export_results(
  modelPath="...my_first_conical.mph",
  sParameters=true,
  fieldImages=[{"expr":"ewfd.normE","filename":"my_first_field.png"}],
  lines=[{"exprs":["ewfd.normE"],"start":[4.5,10],"end":[9,10],"points":40}]
)
```

输出目录类似：

```text
%USERPROFILE%\comsol-agent-workspace\exports\my_first_conical__20261019-112318\
  s_parameters.csv
  my_first_field.png
  line_1.csv
```

到这里，你已经完成了“环境检测 → 建模 → 求解 → 导出”的完整真实链路。

### 2.3 如果中途失败

不要重复点击或盲目重试。先看：

```text
comsol_get_job_status(jobId="...")
comsol_read_log(jobId="...")
```

日志会告诉你问题属于许可、几何、网格、收敛、文件还是预览文件。第 14 节有完整错误码表。

## 3. 它能做什么、不能做什么

### 3.1 能做的事

| 能力 | 说明 |
|---|---|
| 环境检测 | COMSOL 路径、版本、批处理、Java API、许可线索、MATLAB/LiveLink |
| 模型校验 | 文件层检查 + COMSOL 实际加载；区分两者 |
| 从零建模 | 两个经过验证的 2D 轴对称模板：同轴圆锥环形间隙、同轴空气段 |
| 参数修改 | 全局参数、带单位表达式、保存新文件、重新加载回读核对 |
| 求解运行 | Java API 独立进程；可选 `comsolbatch` |
| 参数扫描 | 多参数笛卡尔积、逐组求解、状态记录、超时、取消、断点续跑 |
| 数值评估 | 全局量、体积/面积分、最大/最小/平均、点/截线插值 |
| 结果导出 | S 参数、表格、截线/点数据、PNG 场图、积分结果 |
| 任务管理 | 队列、状态、日志、取消、超时、持久化 |
| 日志诊断 | 许可、内存、网格、收敛、几何、材料/物理场、文件、预览文件 |

### 3.2 明确不能做的事

| 不能做 | 原因 |
|---|---|
| 等离子体模型 | 需要气体种类、压力、电子密度、电子温度、碰撞频率、功率沉积等数据；缺数据时编造会产生伪结果 |
| 气体流动/传热耦合 | 当前模板不含对应物理场、材料和边界条件 |
| 任意几何/任意物理场的“一句话建模” | 当前只开放两个经验证模板；更多模板需要逐个验证 COMSOL API |
| 鼠标/屏幕坐标 GUI 自动化 | 使用 COMSOL 官方 Java API，不做 GUI 点击 |
| 远程执行/公网访问 | 插件只在本机 Harness 主机进程内运行，不监听端口、不上传数据 |
| 自动判断“物理上正确” | 只报告数值与日志；物理判断仍由你负责 |
| 自动删除或覆盖原始模型 | 默认不覆盖；删除需你手动执行 |
| 大型扫描无限运行 | 超过阈值需要显式 `confirm=true`，并给出规模估算 |

### 3.3 适用场景

- 已有 `.mph` 模型，想批量改参数、求解、导出；
- 同轴馈电圆锥/波导类结构的快速电磁基准扫描；
- 需要把“自然语言 → 仿真任务 → 数据 → 下一轮参数”串起来的科研自动化；
- 想先建立可信的电磁基线，再逐步加入等离子体/气流模型。

## 4. 环境准备

### 4.1 操作系统与 COMSOL

已在本机验证：

| 项目 | 实测 |
|---|---|
| Windows | 10.0.26200 x64 |
| COMSOL | `D:\COMSOL62\Multiphysics`，`6.2.0.290` |
| Java | COMSOL 自带 `java\win64\jre`，Java 11.0.20，含 `javac.exe` |
| API | `plugins\com.comsol.api_1.0.0.jar` |
| 许可 | 本机 `license\license.dat`；真实 Java API 检出成功 |
| MATLAB | 检测到 `D:\matlab\2025a\bin\matlab.exe`；未验证许可/LiveLink |

### 4.2 COMSOL 必须包含的组件

确认安装目录下存在：

```text
bin\win64\comsol.exe
bin\win64\comsolbatch.exe
bin\win64\comsolcompile.exe
java\win64\jre\bin\java.exe
java\win64\jre\bin\javac.exe
plugins\com.comsol.api_*.jar
```

缺少 `java\win64\jre` 或 `javac.exe` 时，Java API 桥接无法运行。COMSOL 安装器通常自带完整 JRE；如果被裁剪，需要修复安装。

### 4.3 许可

插件默认不修改任何许可配置。它只读取：

- `COMSOL_HOME`
- `LMCOMSOL_LICENSE_FILE` / `COMSOL_LICENSE_FILE` / `LM_LICENSE_FILE`（若已设置）
- 安装目录下的 `license\license.dat`、`licenseinfo.ini`

真正验证许可的方式是 `comsol_check_environment(deep=true)`：它会创建一个极小模型和 3D 几何，这需要真实检出许可。文件存在**不等于**许可可用。

### 4.4 工作区

默认：

```text
%USERPROFILE%\comsol-agent-workspace\
```

所有新建模型、运行输出、扫描结果、导出文件、任务日志都在这里。你可以通过配置改成别的目录（见第 5.4 节）。

### 4.5 MATLAB / LiveLink（可选）

插件只检测 MATLAB 与 LiveLink 的安装文件，不调用它们。若你需要 MATLAB 联动：

- 确认 MATLAB 许可可用；
- 确认 COMSOL LiveLink for MATLAB 已授权；
- 当前插件**没有**提供 MATLAB 工具，需要你自行验证或在后续版本扩展。

## 5. 安装插件

### 5.1 推荐方式：Harness 插件管理器

在 Harness 中执行：

```text
plugin_manager(
  action="install_bundle",
  target="D:\\path\\to\\comsol-agent"
)
```

`target` 是插件包目录的绝对路径，目录中应包含 `package.json`、`cordis.patch.yml`、`index.js`。

成功时返回：

```json
{
  "stage": "enable",
  "target": "@local/comsol-agent",
  "enabled": true,
  "application": "applied",
  "warnings": []
}
```

### 5.2 验证安装

三种方式任选：

1. 看 Harness 工具列表：应出现 11 个 `comsol_*` 工具；
2. 调用 `comsol_check_environment`；
3. 在插件管理器中查看 `include:comsol-agent` 是否为 `active`。

### 5.3 修改代码后重新加载

Host 插件修改 `index.js`/`lib/*.js` 后，关闭再启用即可：

```text
plugin_manager(action="set_plugin", target="include:comsol-agent", enabled=false)
plugin_manager(action="set_plugin", target="include:comsol-agent", enabled=true)
```

只修改 `java/ComsolBridge.java` 时不需要重载插件：下次工具调用会比较源文件与 class 的时间戳并自动重新编译。

### 5.4 配置

配置写在 bundle 行 `comsol-agent` 的 `config` 中。示例：

```yaml
- insert:
    - id: comsol-agent
      name: '@local/comsol-agent'
      config:
        comsolHome: 'D:\COMSOL62\Multiphysics'
        workspaceRoot: 'D:\comsol-agent-workspace'
        allowedRoots:
          - 'D:\comsol-data'
        maxConcurrentJobs: 1
        maxSweepCombinations: 12
        defaultTimeoutSec: 600
        javaHeap: '-Xmx4g'
```

字段全部可选。完整说明见 [README 第 5 节](../README.md#5-配置)。

### 5.5 安装失败怎么办

| 现象 | 处理 |
|---|---|
| `application` 不是 `applied` | 看 `warnings` 与插件管理器日志；确认包目录有 `package.json` |
| 工具列表没有 `comsol_*` | 重新启用插件；确认 `include:comsol-agent` 为 active |
| 自动检测不到 COMSOL | 配置 `comsolHome` 为 `...\Multiphysics` |
| 导入模块报错 | 检查 `index.js` 语法、`package.json` 的 `type: module` |

## 6. 第一次真实仿真：从零到出图

这一节按顺序带你走一遍，建议照抄参数。

### 6.1 第 1 步：环境检测

```text
comsol_check_environment(deep=true)
```

重点看：

| 字段 | 含义 |
|---|---|
| `comsol.found` | 是否找到安装 |
| `comsol.home` | 实际使用的 COMSOL 目录 |
| `comsol.version` | 版本号 |
| `comsol.java` | 是否有 Java/javac |
| `comsol.license.status` | `checkout-verified-in-probe` 表示真实检出成功 |
| `deepProbe.result.licenseCheckout` | `ok` 表示许可探针通过 |
| `warnings` / `unknowns` | 未验证项；不要忽略 |

注意：`deep=false` 时许可状态可能是 `configured-but-unverified` 或 `unknown`，这是诚实的状态，不是故障。

### 6.2 第 2 步：建立模板模型

本手册使用 `coaxial_conical_gap`。它是一个 2D 轴对称空气域：

```text
(r_in, 0) → (r_out, 0) → (r_out, z_feed)
         → (r_tip_out, z_tip) → (r_tip_in, z_tip)
         → (r_in, z_feed) → 闭合
```

- 底边：同轴 TEM 端口，`Pin=1 W`，`PortName=1`
- 顶边：开放散射边界
- 其余边界：默认 PEC
- 材料：空气（`epsr=1, mur=1, sigma=0`）
- 研究：频域，`plist=freq`

调用：

```text
comsol_create_model(
  template="coaxial_conical_gap",
  name="tutorial_conical",
  solve=true,
  meshSize=4,
  templateParams={
    "r_in":"4.35","r_out":"10","z_feed":"20","z_tip":"60",
    "r_tip_in":"0.5","r_tip_out":"6","freq":"2.45[GHz]","P_in":"1[W]"
  }
)
```

返回中重点看：

- `outputPath`：新模型路径
- `fileCheck.exists/sizeBytes`：文件真的生成了
- `solved`：是否真的求解
- `s11`：端口反射
- `model.meshes[].numElements`：网格是否非零
- `model.solutions[]`：解是否存在
- `modelingAssumptions`：**必须阅读**，它说明这个模型没有做什么

### 6.3 第 3 步：验证模型

```text
comsol_validate_model(modelPath="...tutorial_conical.mph")
```

看两个层面：

- `fileChecks`：文件存在、可读、非空、扩展名正确；
- `modelOpen.ok`：COMSOL 是否**实际加载**成功。

只有 `modelOpen.ok=true` 才说明模型能在 COMSOL 中打开。文件检查通过不代表模型有效。

如果 `previewDetected=true`，说明这是 COMSOL 案例库预览文件，不是完整模型，需要从 COMSOL 案例库下载完整版本。

### 6.4 第 4 步：评估结果

**全局 S11：**

```text
comsol_evaluate_results(
  modelPath="...tutorial_conical.mph",
  expressions=["ewfd.S11"],
  kind="global"
)
```

**体积分/最大值/平均值：**

```text
comsol_evaluate_results(
  modelPath="...tutorial_conical.mph",
  expressions=["ewfd.normE"],
  kind="volume_integral",
  selection=[1]
)
```

**截线：**

```text
comsol_evaluate_results(
  modelPath="...tutorial_conical.mph",
  expressions=["ewfd.normE"],
  kind="line",
  start=[4.5,10],
  end=[9,10],
  points=40
)
```

注意：

- `global` 只能评估全局标量（如 `ewfd.S11`）；
- `ewfd.normE` 是场量，必须用 `volume_integral`、`average`、`maximum`、`minimum`、`point` 或 `line`；
- 2D 轴对称的体积分在实现上使用 `IntSurface + intvolume=on`，单位可能是 `V*m^2`，不是 `V`。

### 6.5 第 5 步：导出

```text
comsol_export_results(
  modelPath="...tutorial_conical.mph",
  sParameters=true,
  tableExpressions=["ewfd.S11"],
  fieldImages=[{"expr":"ewfd.normE","filename":"tutorial_field.png"}],
  lines=[{"exprs":["ewfd.normE"],"start":[4.5,10],"end":[9,10],"points":40,"filename":"tutorial_line.csv"}],
  integrals=[{"exprs":["ewfd.normE"],"evalKind":"volume_integral","selection":[1],"filename":"tutorial_integral.csv"}]
)
```

导出目录默认：

```text
%USERPROFILE%\comsol-agent-workspace\exports\<模型名>__<时间戳>\
```

每个导出项都有独立状态；如果其中一项失败，整体状态为 `failed`，但其他成功文件仍会保留。

### 6.6 第 6 步：打开结果

**S 参数 CSV：**

```csv
solution_index,S11,S11_mag,S11_dB
1,-0.00261231996366+0.253224268922j,0.253237743212,-11.9294313090
```

- `S11`：复数（实部+虚部 j）
- `S11_mag`：`|S11|`
- `S11_dB`：`20 log10(|S11|)`

**截线 CSV：**

```csv
c0,c1,ewfd.normE_real,ewfd.normE_imag
4.50000000000,10.0000000000,2087.52707838,0.00000000000
```

- `c0,c1`：2D 轴对称坐标 `[r,z]`，单位 mm
- `*_real` / `*_imag`：该表达式的实部/虚部

**PNG：** COMSOL 默认表面场图。当前版本未自动添加坐标轴标题/图例；需要出版级图时请自行配置 plot group。

### 6.7 第 7 步：改参数并重算

```text
comsol_set_parameters(
  modelPath="...tutorial_conical.mph",
  params={"freq":"2.40[GHz]","z_tip":"55","r_tip_out":"5.5"}
)
```

返回 `verification`，每项都应 `ok=true`。如果参数不存在，会返回 `PARAM_NOT_FOUND` 并列出可用参数。

然后运行：

```text
comsol_run_model(
  modelPath="...tutorial_conical__params_....mph",
  study="std1",
  solve=true,
  wait=true
)
```

`wait=false`（默认）会立即返回 `jobId`，用 `comsol_get_job_status` 查询；`wait=true` 会等待最终状态。

### 6.8 第 8 步：小规模参数扫描

```text
comsol_parameter_sweep(
  modelPath="...tutorial_conical.mph",
  parameters={
    "freq":["2.40[GHz]","2.45[GHz]"],
    "r_tip_out":["5.5","6"]
  },
  study="std1",
  confirm=true,
  wait=true
)
```

这会运行 4 组，每组独立加载/改参/求解/保存。结果里有：

- `combinations`：总组数
- `succeeded` / `failed`
- `results[]`：每组的 `params`、`status`、`outputPath`、`durationMs`、`logPath`、`error`
- `summaryCsv`：可直接用 Excel 打开的扫描汇总 CSV

超过 `maxSweepCombinations`（默认 12）且未 `confirm=true` 时，工具会先返回 `confirmation_required` 和估算，不会直接启动。

### 6.9 第 9 步：看状态和日志

```text
comsol_get_job_status(jobId="...")
comsol_read_log(jobId="...")
```

`read_log` 会给出：

- `markers`：是否加载模型、是否保存、是否有桥接错误
- `categories[]`：许可/网格/收敛/几何/材料/文件/预览等分类
- `evidence[]`：实际日志行
- `diagnosis` / `confidence`：诊断与置信度
- `conclusion` / `uncertainty`：结论与不确定性说明

日志诊断是启发式的，不能仅凭一个词断定根因。

## 7. 用自然语言下达仿真任务

Agent 会把你的话翻译成工具调用。为了减少来回，建议在描述里包含：

1. **模型路径**（已有模型时）；
2. **研究名**（如 `std1`）；
3. **参数名与单位**（如 `freq=2.45[GHz]`、`gap=2[mm]`）；
4. **扫描范围**和组数上限；
5. **想要的结果**（S11、|E| 最大值、截线、积分、PNG）；
6. **是否允许等待**（大数据量时建议异步）。

### 7.1 可直接复制的提示词

**检查环境**

```text
请用 comsol-agent 检查本机 COMSOL 环境，deep=true，
报告安装路径、版本、Java API、许可真实检出结果和未知项。
```

**建立基准模型**

```text
请用 coaxial_conical_gap 模板建立一个 2D 轴对称模型并求解：
r_in=4.35mm, r_out=10mm, z_feed=20mm, z_tip=60mm,
r_tip_in=0.5mm, r_tip_out=6mm, freq=2.45GHz, P_in=1W,
网格 hauto=4。保存后告诉我 S11、网格单元数和模型假设。
```

**运行已有模型**

```text
请先验证 D:\models\my_model.mph 能否被 COMSOL 打开，
列出物理场、研究和端口；然后运行 std1，保存到工作区，
最后导出 S 参数和 |E| 场图。
```

**参数扫描**

```text
请对 D:\models\my_model.mph 扫描 freq=2.40/2.45/2.50 GHz
和 gap=1/2/3 mm，共 9 组，研究 std1。
先告诉我估算；我确认后再运行。运行完成后汇总每组状态和 S11。
```

**失败诊断**

```text
这个任务失败了：jobId=...。请读取日志，区分是许可、网格、
收敛还是文件问题；给出证据行和下一步排查建议，不要猜。
```

**结果分析**

```text
请读取这 4 个扫描模型的 S11，计算 |S11| 和 dB，
比较不同出口半径的趋势；同时说明这些数值不能证明什么。
```

### 7.2 不建议的说法

- “随便建一个等离子体模型”——缺少参数，插件会拒绝编造。
- “把所有边界都设成 PEC”——插件不会替你决定物理边界；模板有明确假设。
- “帮我优化到最好”——没有目标函数、约束和可信物理模型时，不能自动优化。
- “直接覆盖原模型”——默认禁止；请明确要求另存新文件。

## 8. 11 个工具逐个讲透

> 完整字段表见 [README 第 7 节](../README.md#7-工具参考)。本节给“什么时候用、怎么用、看什么”。

### 8.1 `comsol_check_environment`

**什么时候用**：第一次使用、换电脑、COMSOL 升级、许可异常。

**关键参数**：`deep`（默认 false）。`deep=true` 会真实检出许可并创建小模型，耗时约 20 秒。

**看什么**：

- `comsol.home` / `version`
- `comsol.java.javac.exists`
- `comsol.license.status`
- `deepProbe.result.licenseCheckout`
- `warnings` / `unknowns`

**常见错误**：`COMSOL_NOT_FOUND` → 配置 `comsolHome`。

### 8.2 `comsol_validate_model`

**什么时候用**：拿到任何 `.mph` 后，先验证再运行。

**关键参数**：`openCheck`（默认 true）；`timeoutSec`。

**看什么**：

- `fileChecks`：文件层面
- `modelOpen.ok`：COMSOL 实际加载
- `previewDetected`：是否案例库预览文件
- `modelOpen.model.physics/studies/meshes/solutions`

**常见错误**：`MODEL_IS_APPLICATION_LIBRARY_PREVIEW` → 下载完整模型。

### 8.3 `comsol_create_model`

**什么时候用**：从零建立基准模型；或需要一个可参数化的测试模型。

**支持模板**：

- `coaxial_conical_gap`：同轴圆锥环形间隙空气域
- `rf_coax_air`：均匀同轴空气段
- `rectangular_slot_launcher`：3D WR-340 矩形波导、宽壁纵向开槽、石英窗和外部空气盒；用于宽幅线状等离子体源的冷态电磁评估

**关键参数**：`template`、`templateParams`、`meshSize`、`solve`、`overwrite`。

**看什么**：

- `outputPath` / `fileCheck`
- `solved` / `s11` / `s21` / `slotField`（3D 开槽模板）
- `model.geometries[].domains`
- `model.meshes[].numElements`
- `modelingAssumptions`

**注意**：模板只建立空气/石英冷态电磁基准，不包含等离子体/气流/传热；金属用 PEC 边界表示。3D 开槽模板的槽必须偏离宽壁中心线，居中纵槽与 TE10 表面电流耦合很弱；首轮设计与仿真结果见 [宽幅微波等离子体源设计](宽幅微波等离子体源设计.md)。

### 8.4 `comsol_set_parameters`

**什么时候用**：改全局参数，保存为新模型。

**关键参数**：`params`（字符串或数字）、`outputPath`、`overwrite`（默认 false）、`allowNewParams`。

**看什么**：

- `paramsApplied`：旧值/新值
- `verification[]`：回读值、`matchesExactly`、`ok`
- `allVerified`

**常见错误**：`PARAM_NOT_FOUND` → 参数名错误或模型没有该参数；先 `validate_model` 看参数列表。`OUTPUT_EXISTS` → 输出文件已存在，换路径或 `overwrite=true`。

### 8.5 `comsol_run_model`

**什么时候用**：运行已有模型；改参后求解；需要异步任务。

**关键参数**：`study`、`params`、`solve`、`engine`（`java`/`batch`）、`outputPath`、`overwrite`（默认 false）、`timeoutSec`、`wait`。

**看什么**：

- `jobId` / `status`
- `outputPath` / `outputExists` / `outputSizeBytes`
- `result.studiesRun` / `solutions`
- `result.executionEvidence`：`processStarted/modelLoaded/solveCompleted/outputWritten` 等分阶段证据
- 失败时 `error.code`

**注意**：默认异步；`wait=true` 才等待。`engine="batch"` 使用 `comsolbatch`，输出文件名可能由 COMSOL 自动追加模型名，工具会返回 `actualOutputPath`。

### 8.6 `comsol_parameter_sweep`

**什么时候用**：多组参数批量求解。

**关键参数**：`parameters`（每个参数一个值数组）、`study`、`outputDir`、`overwrite`（默认 false）、`confirm`、`stopOnError`、`timeoutSec`、`maxCombinations`、`resumeJobId`、`wait`。

**看什么**：

- `combinations`
- `result.succeeded/failed`
- `result.results[]` 每组状态与输出
- `stateFile`：断点续跑状态
- `summaryCsv`：扫描汇总 CSV（job 目录、输出目录 jobId 副本、稳定副本）
- `executionEvidence`：单次运行的分阶段证据（在 run_model 结果中）

**注意**：超过阈值先返回 `confirmation_required`；默认串行以保护许可；续跑会跳过已完成组合。

### 8.7 `comsol_get_job_status`

**什么时候用**：异步任务查询；列出最近任务。

**关键参数**：`jobId`（省略则列表）、`limit`。

**看什么**：`status`、`progress`、`durationMs`、`result`、`error`、`logPath`。

**状态**：`queued`、`running`、`succeeded`、`failed`、`timeout`、`cancelled`、`interrupted`。

### 8.8 `comsol_read_log`

**什么时候用**：任何失败、超时、取消后的第一步。

**关键参数**：`jobId`、`maxBytes`。

**看什么**：

- `analysis.categories[]`：分类、证据、诊断、置信度
- `analysis.conclusion`
- `analysis.uncertainty`
- `analysis.tail`

**注意**：日志是启发式诊断；结合 `result.json` 和实际输出文件判断。

### 8.9 `comsol_export_results`

**什么时候用**：求解成功后导出数据/图片。

**关键参数**：

- `sParameters`
- `tableExpressions`
- `fieldImages`
- `lines`
- `samples`
- `integrals`
- `outputDir`
- `overwrite`（默认 false；目标文件已存在时先报 `OUTPUT_EXISTS`）

`filename` 只能是纯文件名，不能包含 `../`、`/`、`\`；重复文件名会被拒绝。成功项与失败项独立记录，部分失败时任务状态为 `failed`，但成功文件仍保留。

**看什么**：

- `items[]`：每项路径、行数、错误
- `fileChecks[]`：文件是否存在、大小
- 整体 `ok`

**注意**：不会假设端口或变量存在；某项失败不会丢掉其他成功文件。

### 8.10 `comsol_evaluate_results`

**什么时候用**：读取数值、计算指标、比较趋势。

**关键参数**：`expressions`、`kind`、`selection`、`coordinates`、`start/end/points`、`uniformity`。

**看什么**：

- `evaluations[].values[]`：实部/虚部
- `unit`
- `featureType`
- `uniformity`（若请求）：公式与适用条件

**注意**：

- `global` 只支持全局标量；
- 场量用积分/平均/最大/最小/点/线；
- 部分表达式失败时，成功值仍返回，整体 `failed`。

### 8.11 `comsol_cancel_job`

**什么时候用**：任务跑错、参数写错、需要释放许可。

**关键参数**：`jobId`、`reason`。

**看什么**：`ok`、`job.status`、`note`。

**注意**：运行中任务会被终止；输出可能不完整，不会被标记成功。

## 9. 已有 .mph 模型的工作流

### 9.1 标准顺序

```text
1. comsol_validate_model(openCheck=true)
2. 读取 modelOpen.model 中的 physics/studies/parameters
3. 确认变量前缀（例如 ewfd）和端口名
4. comsol_evaluate_results / comsol_run_model
5. comsol_export_results
```

### 9.2 先看模型里有什么

`validate_model` 会返回：

- `parameters`：全局参数名与表达式
- `physics[].identifier`：变量前缀（EMW 常见 `ewfd`）
- `physics[].features[]`：端口、PEC、散射等
- `studies[].steps[]`：研究类型
- `meshes[].numElements`
- `solutions[]`

**不要假设**模型一定有 `ewfd`、`S11`、端口或解。先用 `validate_model` 确认。

### 9.3 没有解数据怎么办

如果 `solutions` 为空或 `meshes.numElements=0`：

```text
comsol_run_model(modelPath="...", study="std1", solve=true, wait=true)
```

如果模型没有网格，先确认模型自身是否包含网格序列；`run_model` 不会替你随意改物理场。

### 9.4 端口与 S 参数

`export_results(sParameters=true)` 会自动查找 `Port` 特征，并按 `PortName` 生成 `Sij`。如果模型没有端口，会返回 `NO_PORTS` 错误，而不是伪造 S11。

### 9.5 不是所有 .mph 都能跑

- COMSOL 案例库预览文件：`MODEL_IS_APPLICATION_LIBRARY_PREVIEW`
- 缺失材料/物理场：求解会报变量未定义
- 版本不兼容：可能加载失败
- 需要额外模块：许可错误或物理场创建失败

## 10. 参数扫描与批量结果分析

### 10.1 设计扫描

先想清楚：

- 扫哪些参数？
- 每组是否都需要重新求解？
- 总共多少组？
- 每组大概多久？
- 失败是否继续？
- 是否需要断点续跑？

示例：2 频率 × 2 出口半径 = 4 组。

### 10.2 运行

```text
comsol_parameter_sweep(
  modelPath="...",
  parameters={"freq":["2.40[GHz]","2.45[GHz]"],"r_tip_out":["5.5","6"]},
  study="std1",
  confirm=true,
  stopOnError=true,
  wait=true
)
```

### 10.3 读取汇总

`result.results[]` 每组包含：

```json
{
  "index": 0,
  "params": {"freq": "2.40[GHz]", "r_tip_out": "5.5"},
  "status": "succeeded",
  "outputPath": "...mph",
  "outputExists": true,
  "outputSizeBytes": 1093273,
  "durationMs": 34433,
  "logPath": ".../runs/0001/log.txt",
  "error": null
}
```

### 10.4 用 Python 汇总 S 参数

如果你有自己的后处理脚本，可以按 `outputPath` 逐个调用 `comsol_evaluate_results`，或在 Agent 里让它汇总。示例伪代码：

```python
import json, math
# 假设你把每次 evaluate 的结果保存成 JSON
for row in results:
    s11 = row["evaluations"][0]["values"][0]
    re = s11["real"][0][0]
    im = s11["imag"][0][0]
    mag = math.hypot(re, im)
    db = 20 * math.log10(max(mag, 1e-30))
    print(row["params"], mag, db)
```

### 10.5 断点续跑

```text
comsol_parameter_sweep(
  modelPath="...",
  parameters={...},
  resumeJobId="job-...",
  confirm=true,
  wait=true
)
```

会读取上一次的 `sweep.json`，跳过已成功的组合。实测 4 组全部完成时，续跑耗时 4 ms。

### 10.6 取消

```text
comsol_cancel_job(jobId="job-...", reason="参数写错")
```

取消后输出可能不完整；状态为 `cancelled`。

## 11. 结果数据怎么读、单位怎么理解

### 11.1 S11

- COMSOL 返回复数：`real`、`imag`；
- `|S11| = hypot(real, imag)`；
- `S11(dB) = 20 log10(|S11|)`；
- `|S11|` 越小，反射越少（但不代表结构一定好）；
- `S11` 的定义依赖端口、参考阻抗、激励归一化；不同模型之间不要直接比较。

### 11.2 场量

- `ewfd.normE`：电场模；
- 2D 轴对称的场分量可能是 `Er/Ez/Ephi`，不一定是 `Ex/Ey/Ez`；
- 不要假设变量名；先看模型物理场标识符。

### 11.3 积分、平均、最大值

- `volume_integral`：对域积分；
- `average`：对域平均；
- `maximum`/`minimum`：域内最大/最小；
- `surface_integral`：对边界积分；
- 2D 轴对称的体积分使用 `IntSurface + intvolume=on`，单位可能是 `V*m^2`（对 `|E|`）；
- 单位来自 COMSOL；不要自己猜。

### 11.4 均匀度公式

`uniformity=true` 时使用：

```text
U = 1 - (max - min) / (max + min)
```

适用条件：

- 非负场；
- `max + min ≠ 0`；
- 只对你选择的域/边界有意义。

这是**用户请求的公式**，不是 COMSOL 内建标准量。不同定义会得到不同数值，写论文时必须写明公式。

### 11.5 功率/能量

只有模型真实定义了相应变量（如端口功率、损耗密度、能量密度）时才可评估。不要用 `|E|` 积分直接声称“功率沉积”，除非你明确说明了换算关系和适用条件。

### 11.6 网格与收敛

- 求解成功不等于网格无关；
- 改变网格后 S11/场强可能变化；
- 论文级结果应做网格收敛检查；
- 插件不会自动证明网格无关性。

## 12. COMSOL 环境配置详解

### 12.1 自动探测顺序

1. `COMSOL_HOME` / `COMSOL_ROOT` / `COMSOL_AGENT_COMSOL_HOME` 环境变量；
2. `C:\`、`D:\`、`E:\`、`F:\` 等根目录下 `COMSOL*` 目录；
3. `Program Files` / `Program Files (x86)` 下的 `COMSOL*`；
4. 每个候选目录自身或其 `Multiphysics` 子目录。

只有同时存在 `bin\win64\comsolbatch.exe` 与 `plugins` 才会被接受。

### 12.2 手动指定

```yaml
config:
  comsolHome: 'D:\COMSOL62\Multiphysics'
```

注意指向 `Multiphysics` 目录，不是 `D:\COMSOL62`。

### 12.3 Java API

插件使用 COMSOL 自带：

```text
java\win64\jre\bin\java.exe
java\win64\jre\bin\javac.exe
plugins\*
```

首次使用会编译 `ComsolBridge.java` 到工作区 `.driver\classes`。编译日志：

```text
%USERPROFILE%\comsol-agent-workspace\.driver\compile.log
```

### 12.4 comsolbatch

`engine="batch"` 使用：

```text
bin\win64\comsolbatch.exe -inputfile ... -outputfile ... -batchlog ... -study ...
```

批处理退出码即使失败也可能是 0；插件会根据输出 `.mph` 是否存在、日志是否含致命错误来判断。

### 12.5 许可

- 本机 `license.dat`；
- 浮动许可环境变量（若你已配置）；
- 插件不会修改许可配置；
- `deep=true` 是唯一“真实检出”证据。

### 12.6 版本差异

当前所有 API 方法均在 COMSOL 6.2 上验证。其他版本可能出现：

- 物理场类型名不同；
- 属性名不同（如端口属性大小写）；
- Java API jar 路径不同。

遇到 `Unknown_property` / `Unknown_feature` 时，不要强行重试，先确认版本和 API。

## 13. 安全、文件与许可保护

### 13.1 工作区限制

- 默认所有输出必须在工作区；
- 越界返回 `OUTPUT_OUTSIDE_WORKSPACE`；
- 需要额外目录时配置 `allowedRoots`。

### 13.2 不覆盖原始模型

- `set_parameters` 拒绝 `outputPath == modelPath`；
- `run_model` 拒绝覆盖输入；
- `create_model` 默认不覆盖已有文件，需 `overwrite=true`；
- `set_parameters` / `run_model` / `export_results` / `parameter_sweep` 的目标已存在时默认报 `OUTPUT_EXISTS`，需显式 `overwrite=true`；
- 扫描的稳定汇总 `sweep_summary.csv` 不会被失败任务静默覆盖，失败任务写入独立 jobId 副本。

### 13.3 不执行任意 Shell

- 所有外部程序使用参数数组启动，不拼接 shell 字符串；
- 可执行程序限定为 COMSOL 安装目录下的固定程序；
- 不执行模型内容或自然语言拼接出的命令。

### 13.4 许可保护

- 默认最大并发 1；
- 扫描串行；
- 超过阈值先确认；
- 任务超时/取消会终止进程。

### 13.5 数据隐私

- 插件不向外部服务器上传模型、日志或结果；
- 日志可能包含本机路径；分享日志前自行检查；
- 不要提交 `license.dat`、`licenseinfo.ini`、含个人路径的工作区。

## 14. 故障排查手册

### 14.1 错误码表

| 错误码 | 常见原因 | 处理 |
|---|---|---|
| `COMSOL_NOT_FOUND` | 未检测到安装 | 配置 `comsolHome` |
| `COMSOL_JAVA_MISSING` | 缺 Java | 修复 COMSOL 安装 |
| `COMSOL_JAVAC_MISSING` | 缺 javac | 修复 COMSOL 安装 |
| `COMSOL_PLUGINS_MISSING` | 缺 plugins | 修复安装 |
| `DRIVER_COMPILE_FAILED` | 编译失败 | 看 `compile.log` |
| `MODEL_NOT_FOUND` | 路径错 | 检查绝对路径 |
| `MODEL_BAD_EXTENSION` | 不是 `.mph` | 用正确的模型文件 |
| `MODEL_EMPTY` | 空文件 | 重新获取模型 |
| `MODEL_IS_APPLICATION_LIBRARY_PREVIEW` | 案例库预览文件 | 从案例库下载完整模型 |
| `PARAM_NOT_FOUND` | 参数名不存在 | 用 `validate_model` 查参数 |
| `STUDY_NOT_FOUND` | 研究名错 | 查 `studies[].tag` |
| `COMSOL_TIMEOUT` | 超时 | 提高 `timeoutSec` 或减小模型 |
| `JOB_CANCELLED` | 用户取消 | 重新运行 |
| `OUTPUT_OUTSIDE_WORKSPACE` | 输出越界 | 放工作区或配 `allowedRoots` |
| `OUTPUT_EXISTS` | 文件已存在 | 换路径或 `overwrite=true` |
| `EVALUATION_PARTIAL_FAILURE` | 部分表达式失败 | 看 `results[]` 逐项错误 |
| `EXPORT_PARTIAL_FAILURE` | 部分导出失败 | 看 `items[]`/`fileChecks[]` |
| `LICENSE_ERROR` | 许可问题 | 检查许可文件/服务器/席位 |
| `MESH_ERROR` | 网格问题 | 检查几何/尺寸/网格设置 |
| `CONVERGENCE_ERROR` | 收敛问题 | 检查物理场/求解器/网格 |
| `BATCH_INCOMPLETE` | 批处理未产出文件 | 看 `comsolbatch.log` |

### 14.2 诊断流程

```text
1. comsol_get_job_status(jobId)
2. comsol_read_log(jobId)
3. 看 analysis.categories[].evidence
4. 看 result.json 的 error.code
5. 检查输出文件是否存在、非空
6. 必要时用 validate_model 重新检查模型
```

### 14.3 按现象排查

**COMSOL 进程启动慢**：第一次启动约 10–30 秒，正常；后续调用也是独立进程。

**求解成功但没结果**：检查 `solutions`、`outputExists`、`outputSizeBytes`；有可能是仅加载未求解。

**S11 接近 0**：对均匀同轴空气段 + 吸收边界是可能的；不要直接当作“设计很好”。

**中文乱码**：COMSOL/JVM 本地化差异；以 `tag/type/identifier` 为准。

**扫描很慢**：每组一次 COMSOL 启动；减少组数、增大 `timeoutSec`、使用 `stopOnError`。

**许可被占用**：检查是否有其他 COMSOL 会话；保持 `maxConcurrentJobs=1`。

## 15. 常见问题 FAQ

**Q1：为什么每次调用要 10–30 秒？**  
A：每次工具调用启动独立 COMSOL JVM 并检出许可。这是为了隔离失败、支持取消和完整文件访问。

**Q2：可以同时跑多个扫描吗？**  
A：默认 `maxConcurrentJobs=1`，任务会排队。并发会占用多个许可席位，不建议在共享许可环境开启。

**Q3：可以扫 100 组吗？**  
A：可以，但超过 `maxSweepCombinations` 需要 `confirm=true`。先看估算，确认机器或许可允许。

**Q4：为什么不能直接建等离子体模型？**  
A：缺少气体种类、压力、电子密度、电子温度、碰撞频率等数据。插件拒绝编造，避免产生看似专业但无依据的结果。

**Q5：可以用 3D 吗？**  
A：`comsol_run_model`/`evaluate`/`export` 对已有 3D 模型可用；`create_model` 现在有两个 2D 轴对称模板和一个 3D 矩形波导开槽模板，但任意 3D 几何仍需自行建模或扩展模板。

**Q6：可以用我自己的 .mph 吗？**  
A：可以，先 `validate_model` 确认能打开，再按模型的实际物理场/研究/变量调用。

**Q7：日志在哪里？**  
A：`%USERPROFILE%\comsol-agent-workspace\jobs\<jobId>\log.txt`，同时 `result.json` 保存结构化结果。

**Q8：结果文件在哪里？**  
A：默认在 `exports\<模型名>__<时间戳>\`；扫描在 `sweeps\...`；运行输出在 `runs\...`；新建模型在 `models\...`。

**Q9：怎么改工作区？**  
A：配置 `workspaceRoot`，或设置 `COMSOL_AGENT_WORKSPACE`。

**Q10：怎么卸载插件？**  
A：`plugin_manager(action="remove_bundle", target="@local/comsol-agent")`。工作区数据不会自动删除。

**Q11：为什么 S11 的 CSV 没有频率列？**  
A：当前以 `solution_index` 标识解；多频点研究可对每个频点单独运行，或用 `tableExpressions` 评估频率相关表达式。频率列是后续改进项。

**Q12：结果能直接写论文吗？**  
A：不能直接。需要网格收敛、材料/边界条件核实、实验对比和物理假设说明。插件只提供数值与可追溯日志。

## 16. 维护、升级与卸载

### 16.1 修改代码

- Node 层：修改后关闭/启用插件；
- Java 层：修改 `ComsolBridge.java` 后，下次调用自动重新编译；
- 重新编译日志：`workspace\.driver\compile.log`。

### 16.2 升级

- 用新的插件目录替换旧目录；
- 重新执行 `install_bundle`；
- 或修改 `package.json` 版本后重新安装；
- 保留工作区数据（不要删除 `jobs/models/runs/sweeps/exports`）。

### 16.3 卸载

```text
plugin_manager(action="remove_bundle", target="@local/comsol-agent")
```

卸载不会删除工作区；如需清理，请手动删除 `%USERPROFILE%\comsol-agent-workspace`。

### 16.4 备份

建议备份：

- 重要 `.mph`；
- `exports/`、`sweeps/` 结果；
- `jobs/*/log.txt` 与 `result.json`（用于追溯）。

不需要备份 `.driver/classes`（可重新编译）。
